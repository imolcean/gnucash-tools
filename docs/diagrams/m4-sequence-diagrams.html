Session lifecycle

A login opens a Session: the user's own Hikari pool (max 2 connections, none kept idle) built with their Postgres username and password, wrapped in a GnuCashBook. The Session is the Spring Security principal, so it lives in the HTTP session, which never expires (server.servlet.session.timeout=-1). The pool closes on logout, when the HTTP session is destroyed, or when the app stops (ADR-0006).

  rect rgba(127,127,127,0.08)
  Note over U,PG: Login
  U->>SS: POST /login (username, password)
  SS->>BAP: authenticate(token)
  alt DB host or name not configured
    BAP-->>SS: AuthenticationServiceException
  else configured
    BAP->>Ss: open(username, password)
    Ss->>S: new HikariDataSource(config)
    S->>PG: connect as username (once, at pool build)
    alt Postgres accepts
      PG-->>S: connection
      Ss->>Ss: open.add(session)
      Ss-->>BAP: Session
      BAP-->>SS: authenticated(principal = Session, no password)
      SS->>SS: new session id, store SecurityContext in HttpSession
      SS-->>U: 302 / + session cookie
    else SQLSTATE 28xxx (wrong password, unknown role)
      PG-->>S: refused
      S-->>BAP: PoolInitializationException
      BAP-->>SS: BadCredentialsException
      SS-->>U: 302 /login?error → "wrong username or password"
    else any other failure
      BAP-->>SS: AuthenticationServiceException (cause logged)
      SS-->>U: 302 /login?error → "cannot reach the book"
    end
  end
  end

  rect rgba(127,127,127,0.08)
  Note over U,PG: Each request while logged in
  U->>SS: GET /accounts (cookie)
  SS->>SS: load SecurityContext from HttpSession
  SS->>C: @AuthenticationPrincipal Session
  C->>S: book().lock(), schemaStatus() (BannerAdvice)
  C->>S: book().accountTree()
  S->>PG: borrow or open a connection, query
  PG-->>S: rows
  C-->>U: HTML page
  end

  rect rgba(127,127,127,0.08)
  Note over U,PG: End of the session
  alt Logout
    U->>SS: POST /logout
    SS->>SC: logout(authentication)
    SC->>Ss: close(session)
    Ss->>Ss: open.remove(session)
    Ss->>S: close()
    S->>PG: close connections
    SS->>SS: invalidate HttpSession, clear context
    SS-->>U: 302 /login?logout
  else HttpSession destroyed (invalidated by the container)
    SS->>SC: HttpSessionDestroyedEvent (via HttpSessionEventPublisher)
    SC->>Ss: close(session) for each SecurityContext
    Ss->>S: close()
    S->>PG: close connections
  else App stops
    Ss->>Ss: @PreDestroy closeAll()
    Ss->>S: close() for every open Session
    S->>PG: close connections
  end
  Note over BAP,PG: Closing twice is harmless: remove() is a no-op and Hikari ignores a second close()
  end
