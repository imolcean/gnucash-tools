Session lifecycle

A login opens a Session: the user's own Hikari pool (max 2 connections, none kept idle) built with their Postgres username and password, wrapped in a GnuCashBook. The Session is the Spring Security principal, so it lives in the HTTP session, which never expires (server.servlet.session.timeout=-1). The pool closes on logout, when the HTTP session is destroyed, or when the app stops (ADR-0006).

Login, logout and connection pools

Each login gets its own Hikari pool named book-N, opened with the user's Postgres login. The pool holds at most 2 connections and keeps none idle for long: after a minute without use it holds no connection, and the next request reconnects with the login stored inside the pool. Logout closes the pool. Spring Security then invalidates the HTTP session, which asks SessionCloser to close the same pool a second time; that call does nothing.
